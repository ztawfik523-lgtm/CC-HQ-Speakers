## Reevaluated gaps discovered later the same day

The original handoff did not account for:

- packet-send exceptions not being isolated from authoritative server transitions;
- `playPrepared()` rollback/session inconsistency on a thrown start;
- playback reference ownership being cleared before final store release succeeds;
- the lack of a sliding consume/discard operation in `FiniteRangeWindow`;
- incomplete deterministic coverage of the original M1F acceptance matrix;
- no recorded focused Minecraft M1F runtime transport acceptance.

Therefore the old phrase `M1F source/test/CI complete` is historical, not current.
